## The plan (swarm.1)

**One story = two files** in `stories/<id>/`:
- `story.json`: the deck. An ordered list of scenes, each built only from **primitives**: title, statement, bullets, quote (a person's own words), compare (before/after), ladder (n levels, animated), flow (A → B → C), graph (nodes and edges), counter, table (attempt / access / mandate), and embed (any existing stage scene, by id). The same look as the stage: stage/themes.css, the same captions, focus mode, play-all.
- `trail.json`: how it was made. One node per transaction: who (person, conductor, lead, swarm.1, storyteller, dev, designer, GitHub Action, model), where it ran (Claude Code cloud, GitHub Actions, the browser), with what (ABP on/off, GitHub compute yes/no, model and cost when a model was called), when (UTC from commits, inbox times and session events), and the artefact it passed on (voice memo → transcript → brief.md → story.json → page). Hashes, never model text.

**Pages:** `pages/stories.html` (the list) and `pages/story.html?s=<id>`, with four modes: **Present** (the deck), **Timeline** (the trail on a time axis), **Graph** (who passed what to whom) and **Delivery** (the artefacts, each with its hash, commit and link).

**Part one (today, with the team):** the question goes to each person through their own conductor. The person answers by voice (dictated in the Claude app), and the conductor sends the answer, with its times, to swarm.1's inbox (`admin/tools/inboxes.py send ... --to swarm.1.fringe-dinis`). swarm.1 drains at each wake. storytelling.1 writes story.json, swarm.1.dev's kit renders it, and `tools/story-trail.mjs` (swarm.1) builds trail.json from the inbox times, the commits and the sessions. The warm-up questions: what is RiskMandate? what is an agent behaviour policy? what is the app you have been working on? Some stories run under ABP and some without, some on GitHub compute and some not, and the trail says which.

**Part two (the stand, browser only, simulations only):** record → transcribe (a model through OpenRouter) → a coordinator (Sonnet) that may call only the primitives, as tools → the deck builds on screen while the making-of draws itself beside it, node by node, with times. A disposable key, encrypted with a passphrase that only the stand's device holds; never in chat, never in plain text in git.

**Who:**
- swarm.1.dev: the story kit (`assets/story-kit.js`: primitives, player, tool schema).
- swarm.1.designer: stories.html and story.html, in the stage's UI.
- storytelling.1: Dinis's own stories, as the warm-up, plus the team's answers.
- swarm.1: trail.json, the conductors' path, the stand's coordinator and key handling.
